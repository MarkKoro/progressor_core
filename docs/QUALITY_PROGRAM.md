# Правила технического качества и интерфейсов

Канонический код Core хранится только в `MarkKoro/progressor_core`.
Food, Gym Diary и Supply сохраняют свои базы, Telegram consumers и API.
Общий интерфейс обслуживает Core; предметные операции выполняет владелец базы.
Изменения публикуются обычным fast-forward непосредственно в `main`.

Полная система проверки: [технические правила](TECHNICAL_QUALITY_STANDARD.md),
[правила интерфейсов](USER_EXPERIENCE_STANDARD.md),
[исследование и первичные источники](QUALITY_RESEARCH.md).
Это критерии проверки конкретного изменения, а не обещание отсутствия любых багов.

## Обязательные границы

1. Идентичность подтверждается Telegram proof или предназначенным для получателя
   подписанным утверждением. Локальные ID трёх баз не равны Telegram ID.
2. Просмотр не создаёт занятия, не удаляет историю и не запускает ИИ.
   Окончание подписки ограничивает возможности, сохраняя данные.
3. Общий контекст требует оплаченного получателя и источника, свежих снимков,
   пользовательских настроек и существующего согласия Supply.
   Тренерские права Gym сами по себе не открывают Food/Supply подопечного.
4. Дозировка — введённая владельцем надпись с упаковки. Результат модели не
   становится дозировкой, в том числе при показе старых daily plans.
   Пустой обоснованный результат ИИ допустим и не требует добавки «на всякий случай».
5. Подсказки используют записанные факты, явно обозначают неполный журнал и оценки.
   Пропущенная запись не доказывает дефицит. Калории не определяются по повторениям;
   расход не прибавляется к питанию автоматически.
6. Денежные записи, grants, refunds и версии протокола сохраняются при откате кода.
   Пробный/подарочный доступ не создаёт денежный зачёт.

## Горячие пути и конкурентность

Синхронная SQLite-операция в async endpoint выполняется целиком вне event loop,
включая открытие соединения, транзакцию и закрытие. Не передавайте одно SQLite
соединение между потоками. Таймаут внешнего сервиса не блокирует readiness.

`Store.context_snapshot()` — проекция только для одного запроса. Общий контекст,
ритм и подсказки используют её совместно. Она не кэширует разрешения между
запросами и не заменяет полный `Store.data()` для предметных читателей.
`Store.settings_snapshot()` отдельно читает профили, вес и краткие факты тренировок
для общих настроек. Вес, согласия тренера и ритм используют одну выборку; большие
векторы нагрузки и журналы еды/приёмов для этого не декодируются.
Индивидуальные блюда не декодируются повторно вместо готовых дневных итогов.
Для Supply сохраняются последние 90 отметок и последнее реальное принятие,
нужное для завершения проверки цели. Общий счётчик считается отдельно по всем
сохранённым отметкам. Проверка подписки читает только membership profiles.
Тренерский top-5 продолжает читать разрешённые блюда по отдельному согласию.

Сводные значения по последним 90 отметкам нельзя выдавать за полную статистику
недели, если у человека их больше 90: определяйте окно и покрытие отдельно.
При новых правилах подбирайте выборку под факты правила и проверяйте границы окна.

Supply рассчитывает историю ограниченными пакетными запросами. Каталог достижений
не переписывается на каждую отметку; длинное чтение не удерживает writer lock.
Gym ищет предыдущую подходящую тренировку до чтения её подходов.
Повторная отметка принятия сохраняет первый снимок дозировки; явное снятие и
повторная отметка создают новый снимок введённой владельцем надписи.

Supply check-in имеет устойчивые состояния processing/done/failed и lease.
Повтор использует исходные ответы и исходный канал. GET результата не вызывает ИИ.
Локальная версия загрузки защищает переход Сегодня → Завтра → Сегодня.

## Состояния интерфейса

Критический `shared/bootstrap.v1.js` имеет три одинаковых distribution mirrors:
`webapp/assets/progressor-bootstrap.v1.js` в Gym/Supply и
`static/webapp/assets/progressor-bootstrap.v1.js` в Food. Каноническая версия
редактируется только в Core и переносится вместе с ботами; update-all сверяет байты.
Это маленький клиент запуска, не вторая реализация Core. Он захватывает исходный
Telegram launch до изменения URL, сохраняет cross-navigation assertions и загружает
единственный общий UI с Core асинхронно. Собственный валидируемый native proof не
должен ждать Core. При переходе из другого продукта по-прежнему нужна Core assertion.
Сбой Core имеет конечный таймаут и backoff; явное повторное действие может обновить сессию.

Проверяйте загрузку, готовые данные, пустую историю, сохранение, ошибку, устаревшие
данные и отсутствие доступа отдельно. Ответ загрузки должен сам обновлять экран;
нельзя рассчитывать на случайную последующую перерисовку другого запроса.
При ошибке загрузки старый результат остаётся виден с объяснением и безопасным
повторным чтением. Нельзя повторять расчёт по неизвестному устаревшему состоянию.

`ProgressorDomain.isReady()` означает завершение собственной начальной загрузки.
Подсказка не появляется поверх skeleton, onboarding, формы или другого диалога.
Общая панель подписок не закрывается при выборе карточки внутри перестроенного DOM.
Сохраняйте одинаковые кнопки рублей и Stars и существующий внешний payment flow.

Закрытые drawer/modal не доступны с клавиатуры. Активный диалог удерживает Tab,
Escape/Telegram Back отменяют или закрывают его и возвращают фокус инициатору.
Проверяйте это отдельно для общих и предметных окон. Не подтверждайте удаление или
платёж обработчиком Back. Компактная навигация сохраняет доступную область касания.

Food сохраняет исторический контракт дня: Москва, UTC+3, независимо от часового
пояса телефона. Подпись у дня показывает этот выбор. Часовой пояс напоминаний
пользователя — отдельная настройка; старые записи не сдвигаются между датами.

## Зависимости и обновление

Python 3.12/Linux: `requirements.txt` объявляет все runtime roots, включая SDK
OpenAI там, где он импортируется. `constraints.txt` закрепляет полный разрешённый
граф. Обновляйте их вместе после отдельного разрешения зависимостей, `pip check`,
проверки актуальных advisory и применимых регрессий. Наличие старого пакета в venv
не является объявлением зависимости. Windows имеет собственные платформенные extras.

`update-all` готовит новое окружение из репозитория. Старый список пакетов остаётся
диагностикой; пакеты из старого venv не переносятся скрыто. Прежнее окружение не
меняется и остаётся доступным для отката. Fingerprint учитывает requirements и constraints.
См. [UPDATE_ALL.md](UPDATE_ALL.md) и [DEPLOYMENT.md](DEPLOYMENT.md).

`deploy/sqlite-runtime.json` закрепляет отдельную SQLite с проверяемым исходником.
Установщик проверяет библиотеку в интерпретаторах всех затронутых служб и в реально
запущенных процессах. Глобальная системная библиотека и старые runtimes не заменяются.
Перед переключением проверяются consistent backup, восстановление вне сервера,
свободное место и совместимость финансового протокола. Откат кода не восстанавливает
старую базу поверх новых пользовательских записей.

## Как проверять изменение

Сначала воспроизведите конкретный отказ на временных базах. Проверяйте владельца,
отказ доступа, устаревший ответ, повтор и сохранность подтверждённой записи.
Для скорости: 100 измерений после прогрева, 5 параллельных клиентов, малый и большой
наборы, сырые времена и ошибки. Бюджеты: обычные чтение/запись p95 ≤500 мс,
общий контекст ≤1000 мс. Не запускайте одновременно другой нагрузочный тест.

Linux unittest/pytest используют dummy credentials и запрещённую внешнюю сеть.
Браузер проверяет настоящий HTML/API на вымышленных данных и синтетическом Telegram
SDK: узкие экраны, 200% текст, темы, фокус, ошибки и сочетания подписок.
Такая проверка не равна испытанию физического Telegram клиента или полной
сертификации доступности. Реальные платежи, платный ИИ и дополнительный consumer
не нужны для регрессий. Фиксируйте точные исходники, результат и ограничение охвата.


## Membership and history read boundaries

Subscription display reads a consistent, account-owned membership snapshot. Only a source profile with no profile_kind supplies native expiry; coach-link rows cannot override it. Context, settings, and membership multi-query reads begin one read transaction. An account/deletion/entity index supports the projections. Context retains workout headers but strips historical strength vectors outside the requested day and its 90-day comparison window; historical requests use their requested day, with timezone boundary margins. Full owned data remains available to explicitly authorized detailed history and coach top-dish calculations.

## Equal payment choices and retained tariffs

The standard selection presents 1, 6, and 12 months as three RUB/Stars pairs in the shared WebApp and native consumers. Other existing periods remain under Other periods; an eligible alignment quote remains directly visible. The external subscription page expands an explicitly selected extra period. No price, SKU, settled order, duration, provider confirmation, or paid-credit formula changes. Food native prices are read from current owner settings rather than an import-time default. Existing Stars-only callback names remain compatible and lead to both choices. The shared bot helper is synchronized to all three repositories.
