# Единая шкала маршрутов JQ-v1

Версия1.0. Зафиксирована до генерации идеальных моделей. Это проектная экспертная шкала, а не валидированный психологический тест и не статистика пользователей. Основания: [исследование удобства](JOURNEY_USABILITY_RESEARCH.md), [методы проверки промптов](JOURNEY_PROMPT_RESEARCH.md).

## Одна мера и обязательные условия

**Q = 100 × сумма девяти оценок /36.** Каждый критерий0–4, равный вес1/9. Равные веса выбраны для прозрачного сравнения; они не выведены из числа пользователей популярных приложений.

Gates проверяются до суммы. Fail блокирует решение; unknown остаётся pending. Высокий Q не компенсирует нарушение. Условия относятся к указанной задаче и обязательной матрице состояний, а не доказывают отсутствие любых ошибок.

| Gate | Обязательное условие | Что блокирует |
|---|---|---|
| G1 | Права, согласие и минимизация | Чужие данные, обходentitlement/consent, лишняя передача контекста, ссылка принята за право доступа. |
| G2 | Сохранность и однократность | Потеря/повтор пользовательской или финансовой записи, удаление истории приexpiry/rest, конфликт источников скрыт. |
| G3 | Честность состояния | Нет записи превращено в0/дефицит/невыполнение; оценка/stale выданы за подтверждённый свежий факт; ложный успех. |
| G4 | Безопасные значимые решения | Диагноз/доза/существенная смена цели или плана без основания и пользовательского контроля. |
| G5 | Понятный платёж | Неясные цена/валюта/срок/состав, ложная оплата, повтор покупки, доступ без подтверждённого платежа. |
| G6 | Основной путь и выход проходимы | Обязательная задача/выход блокированы фокусом, перекрытием, невернымBack/Close или недоступным управлением. |
| G7 | Сквозное уважение настроек | Отдых/opt-out/отзыв согласия/expiry обходятся другим ботом; отклонённая завершённая подсказка навязывается снова. |

## Наблюдаемые якоря

Один и тот же результат/контекст/набор состояний оцениваются одинаково. Для каждого критерия сохраняются основание, среда и проверенные состояния. Неизвестный балл — null, не0 и не4.

### s1 — Достижение результата

Наблюдать: Correct persisted outcome; Required entry points; Completed prompt retirement.

| Балл | Основание |
|---:|---|
| 0 | Результат недоступен или неверен |
| 1 | Только сведения о результате; завершить задачу приходится вне предусмотренного пути |
| 2 | Основной исход достигнут, но важное условие/вход требует обхода |
| 3 | Заявленный исход полностью получен и подтверждён во всех основных обязательных состояниях |
| 4 | Исход столь же надёжен при повторном входе/изменении условий; завершённое действие явно больше не требуется |

### s2 — Понятность и происхождение

Наблюдать: Result/scope/source/day/uncertainty explained; Consistent labels; Next action.

| Балл | Основание |
|---:|---|
| 0 | Интерфейс вводит в заблуждение о данных/доступе/действии |
| 1 | Названия, последствия или жаргон требуют догадки |
| 2 | Действие понятно, но существенный источник/период/ограничение скрыт |
| 3 | Результат, применимый период, происхождение и следующий шаг ясны |
| 4 | Краткий основной текст дополнен объяснением по запросу; неизвестность/ограничения видны без перегрузки |

### s3 — Усилие и повторный ввод

Наблюдать: Required decisions/navigation/duplicate fields; Forced optional setup.

| Балл | Основание |
|---:|---|
| 0 | Ненужный повторный ввод препятствует задаче или вынуждает выдумывать отсутствующее |
| 1 | Нужно повторить ключевые сведения/пройти ненужную настройку |
| 2 | Часть контекста используется, но есть устранимые шаги/поля |
| 3 | Нет устранимого повторного ввода; обязательны сведения только для текущего результата |
| 4 | Обычное повторное действие короче первого; разрешённый контекст используется с контролем без скрытой смены смысла |

### s4 — Непрерывность и возврат

Наблюдать: Intent and draft survival; Exact deep-link destination; Return destination.

| Балл | Основание |
|---:|---|
| 0 | Переход теряет намерение/черновик |
| 1 | Открывается общий экран без понятного продолжения/возврата |
| 2 | Продукт открыт, но часть контекста/возврат надо восстановить вручную |
| 3 | Открывается конкретное действие с разрешённым контекстом и понятным возвратом |
| 4 | Намерение сохраняется при закрытии/повторе/возврате до завершения, отмены или явной утраты актуальности |

### s5 — Контроль и исправление

Наблюдать: Decline/pause/edit/undo; Consequential mutation review; Cross-surface settings.

| Балл | Основание |
|---:|---|
| 0 | Существенное изменение самовольно или неисправимо |
| 1 | Доступен только грубый общий отказ/удаление |
| 2 | Можно скрыть подсказку либо исправить источник, но контроль фрагментарен |
| 3 | Можно отказаться, исправить источник, управлять связью и отменить допустимое изменение |
| 4 | Контроль последователен во всех входах; последствия/срок/состояние исправления понятны, другие поверхности настройку не обходят |

### s6 — Уместность и спокойствие

Наблюдать: Unrequested interruption; Duplicate/post-completion hints; Notification budget.

| Балл | Основание |
|---:|---|
| 0 | Повторные/завершённые подсказки мешают основной задаче |
| 1 | Частые ненужные модальные предложения/сообщения |
| 2 | Есть лимит частоты, но смысловая актуальность/завершение учтены неполно |
| 3 | Подсказка относится к текущей задаче, не дублируется; отказ/отдых/завершение соблюдаются |
| 4 | Помощь компактна и своевременна; поводы объединены, можно спокойно продолжить без ответа |

### s7 — Устойчивость к сбоям и неполноте

Наблюдать: Local outcome under unavailable Core/provider; Safe retry; Late read/edit/delete/revoke/expiry.

| Балл | Основание |
|---:|---|
| 0 | Сбой приводит к неверным данным/потере записи |
| 1 | Вторичная интеграция блокирует основное действие |
| 2 | Ошибка обозначена, но восстановление требует лишнего ввода/перезапуска |
| 3 | Локальная задача сохранена, неизвестность честная, повтор безопасен |
| 4 | Правка/удаление/запоздалый ответ/отзыв доступа/возврат последовательны без двойного действия и навязчивых повторов |

### s8 — Доступность и адаптивность

Наблюдать: Semantic names/focus/keyboard; Narrow viewport/text zoom/themes; Target geometry/assistive input.

| Балл | Основание |
|---:|---|
| 0 | Основное действие/выход недоступны в обязательной среде |
| 1 | Существенные барьеры чтения/нажатия/понимания статуса |
| 2 | Основной вид проходим, но обязательные масштаб/тема/фокус/семантика требуют исправлений |
| 3 | Применимые критерии приёмкиAA и проектные ориентиры выполнены на обязательной матрице |
| 4 | Последовательная работа с увеличенным текстом/вспомогательным вводом/динамическим обновлением и возвратом; жесты не обязательны |

### s9 — Скорость и цена исполнения

Наблюдать: Visible feedback delay; Field INP/LCP/CLS when measurable; Backend p95 separately; Provider calls/retry/cost.

| Балл | Основание |
|---:|---|
| 0 | Ожидание/расход не ограничены или просмотр вызывает ненужные платные генерации |
| 1 | Медленное блокирование без состояния и безопасного выхода |
| 2 | Вызовы ограничены, но есть устранимое ожидание/перечитывание/повтор |
| 3 | Бюджеты задачи заданы и соблюдены; чтение/арифметика безAI, ожидание обозначено |
| 4 | Быстрый отклик, выход во время ожидания, только нужное обновление и ограниченные ресурсы при малой/большой истории |

## Агрегация и зрелость доказательства

Сначала сохраняются сценарные строки. Оценка маршрута по критерию — минимум среди обязательных состояний: успешный desktop не скрывает сломанный обязательный телефон. Если состояние неизвестно, окончательная оценка не считается полной.

Для u неизвестных критериев и суммы известных k диапазон Q: [100×k/36;100×(k+4u)/36]. Знаменатель не сокращается. Диапазон означает недостающие сведения, не статистический доверительный интервал.

Стадии evidence: concept → code → automated → device → user. Они записываются отдельно от Q. Концептуальный прогноз не называется наблюдённым улучшением. Тест браузера не подтверждает физическое устройство, A/B-результат или удержание. Не умножать балл на вымышленную «достоверность».

## Сопоставление без подмены условий

Для каждого бота три подхода A/B/C применяются ко всем трём его seed-профилям: всего27 ячеек. Для межпродуктовых моделей каждый подход того же входа проверяется на одинаковых горизонтах день/неделя/возврат: ещё27 ячеек. Сырые баллы разных людей/намерений напрямую не ранжируются.

Первый круг — концепции до знакомства с текущими экранами. Второй — после проверки исходников/выполнимости и контрольных случаев. Пары показываются в обоих порядках; несовпадение сохраняется. Это процедура модельной проверки, не слепой эксперимент с людьми.

Шкала не выбирает автоматически самый большой продукт. Учитываются конкретный выигрыш, поведение при отказе и стоимость реализации. Повтор идеи не подтверждает её пользу. Подписки и дополнительные источники не должны становиться условием базового собственного действия.

## Проектные ориентиры приёмки

Нативные единицы Apple pt, Android dp и Web CSSpx различаются. Для наших WebApps проектный ориентир частых touch-действий44 CSSpx, где нужно48; это не утверждение, что WCAG требует44px. Применимые WCAG2.2 AA проверяются по исходным критериям и исключениям. Матрица:320/390/736px, светлая/тёмная тема,200% текста, keyboard/focus/Back/Close, ожидание и восстановление.

Сетевые показатели пользователя не выводить из backend p95. Существующие локальные бюджеты чтения500мс/полного контекста1000мс сохраняются для соответствующих изолированных измерений. Просмотр/переход/арифметика —0 платных AI-вызовов. Для нового поведения задаётся конкретная проверка отклика и ресурсов.

Каждый изменённый маршрут проверяется на основной операции и значимых отказах/возврате. Все применимые gates должны иметь именованное evidence до публикации; реальные платежи/устройства остаются явно не проверенными, если тестов не было.

## Неизменность

Изменение весов/якорей требует новой версии, причины и пересчёта всех сопоставимых вариантов. Исходные оценки и черновики сохраняются. Контрольные SHA находятся в work/journeys-20261017/method-freeze.json.
